# Week 2 – Blockchain Architecture, Nodes, and Consensus
## 2.0 Week Overview

This week, we will internalize how the decentralized network functions as a unified "World Computer". We will dissect the physical and logical components that make the Ethereum network tick, focusing on the roles of nodes, the structure of the block, and the lifecycle of a transaction from a user’s wallet to permanent finality on the chain. 

Crucially, we will study Ethereum's layered architecture (Execution and Consensus layers) and understand how Proof-of-Stake (PoS) provides security and agreement across the distributed system. Finally, we will confront the scalability challenges of Layer 1 (L1), which necessitates the modern developer's default choice: Layer 2 (L2) solutions, setting the stage for smart contract development.

## 2.1 Weekly Learning Objectives

By the end of this week, students will be able to:

1. **Describe the Ethereum Architecture:** Differentiate between the Execution Layer (EVM) and the Consensus Layer (PoS) and explain how they interact via client software to maintain the canonical state of the network.
2. **Explain Transaction Flow:** Detail the life cycle of a transaction from submission into the Mempool to its inclusion in a block, validation, and finalization.
3. **Analyze Block Structure:** Identify the key fields within a block header (e.g., parent hash, state root) that ensure cryptographic linkage and maintain immutability.
4. **Define Node Roles:** Distinguish between Full, Light, and Archive nodes, and articulate the importance of node diversity for network resilience.
5. **Query On-Chain Data:** Use command-line tools (Foundry `cast`) and client-side JavaScript (`Ethers.js`) to programmatically read block data and monitor network status.
